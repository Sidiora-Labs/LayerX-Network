# Hosted Human service

The image builds both real binaries from `human/crates/layerx-human-service` with the workspace lockfile. The Deployment runs the HTTPS API and its privileged production components as UID 4020, sharing `/run/layerx/human/components.sock`. Principal rows, custody references and the authentication index persist on `layerx-human-state`. The beta cluster issues the API certificate from its CA and exposes `layerx-human.layerx-testnet.svc:9443`. Readiness verifies that CA and requires HTTP 200 from the actual `/readyz` route; `/livez` only reports process liveness.

`human/apps/web/next.config.mjs` selects `output: "standalone"`, and the application contains server session handling and API routes. It requires a separate Node.js runtime (`package.json` requires Node 24 or later); the Rust API does not serve a static web build. This deployment includes only the service. The web origin is `https://human.testnet.layerx.network`; this declares the API's allowed origin, not a deployed public website.

## Required production dependencies

The cluster does not yet provide the full Human production component graph. The required `layerx-human-components-config` Secret must supply the remaining exact environment names read by `ProductionComponentsConfig::from_environment` in `human/crates/layerx-human-service/src/server/production_components.rs` and `MovementProviderConfig::from_environment` in `server/movement_provider.rs`. No defaults or generated substitute identities are supplied for those mandatory settings. The Deployment supplies the component socket, UID, worker/queue and maintenance bounds, and the three persistent storage roots directly from the binary's configuration surface.

The configuration includes passkey RP/origin and ceremony/session/retention bounds; tenancy, authentication-index and stream-cursor keys; agentd socket and bounded transport settings; security, identity and movement sockets with their actual peer credentials and transport limits; mTLS KMS endpoint, server identity, certificate paths and transport limits; network/protocol version; agent actor, authority, owner, purpose catalog and recovery policy; and the actual Paxeer custody RPC, chain, trust anchor, exit/withdrawal contracts and confirmation policy. File inputs belong in the required `layerx-human-component-material` Secret mounted at `/run/layerx/material`. Secrets are deliberately not created with fabricated material.

Provider processes must be wired to the shared pod socket volume using their real protocols. `layerx-agent-boundary` is an HTTPS LNI submission adapter, not agentd's Unix contract. The hosted identity service is an HTTP provisioning service, not Human's framed Unix identity provider. The internal signing KMS is not the Human mTLS custody KMS. A ready production component requires agent/core, KMS/custody, security, identity, movement and Paxeer probes to succeed. Provider hosting and the corresponding narrowly scoped egress policies remain required before this Deployment can become ready; the policy currently admits DNS only for egress. No general network egress is granted for unspecified providers.

Ingress admits the two real internal Human adapters (`layerx-internal-journeys` and `layerx-internal-approvals`) and qualification pods labelled `app: layerx-qualification` in `layerx-testnet`. Host qualification uses the cluster script's loopback port-forward on 19453 and `LAYERX_QUALIFICATION_HUMAN_URL`. The gateway has no Human proxy and receives no Human ingress permission.

## Sessions

`ProductionComponents` handles passkey registration/assertion and `session.open`; opening a session requires a verified assertion from the authentication index and registers the session authority through agentd. An identity-service bearer or a gateway key is not a Human session cookie. The cluster creates empty journeys/approvals credential maps. A real principal must complete the passkey ceremony before its authenticated Human cookie can be provisioned into the adapters' principal-to-file maps. The cluster does not synthesize cookies or claim readiness without those dependencies.

Namespace teardown deletes the Human Deployment, TLS Secret and PVC along with the other disposable beta resources. The component socket uses an ephemeral shared volume so a stale socket cannot survive pod replacement.
