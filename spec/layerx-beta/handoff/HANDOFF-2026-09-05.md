## The one real blocker, and its fix (task 6.10 — do this FIRST)

`build/bin/layerxd --serve` cannot bootstrap on main. Owner commit 093d2b90
(2026-09-01) added at `cmd/layerxd/lxp_daemon_process.c:3146-3148`:

    if (status == LXP_OK && process->evidence_store.verify_finality_authority == NULL)
        status = LXP_ERR_MODULE_DISABLED;

and nothing in `cmd/layerxd` ever calls
`lxp_daemon_evidence_bind_finality_authority` or passes a verifier to
`lxp_daemon_evidence_open`. Evidence: `spec/layerx-beta/qualification.kvx`
`[observation.6.3.1]` (strace + linked diagnostic). Every sequencer-backed
test in 6.1, 6.2, 6.3, 6.4 hits this.

What the verifier must be (the core's own test defines the semantics —
`tests/storage/lxp_test_finality_evidence.c:249-290`): given
`(certificate, bonded_set, requirements, settlement_registration)`:

- `lxp_checkpoint_certificate_hash(&certificate->checkpoint)` must equal
  `registration->checkpoint_id`;
- `certificate->attestations[0].paxeer_chain_id` and
  `.paxeer_settlement_contract` must equal the registration's and the
  daemon's configured chain id / settlement contract;
- `lxp_checkpoint_finalisable(&state, cert, bonded_set, requirements, ...)`
  must report finalisable (threshold met) — core API in
  `include/layerx/lxp_paxeer.h` (`lxp_paxeer_verify_cert`) and
  `src/paxeer/lxp_paxeer_client.c:57`;
- an INDEPENDENT observation that the registration really happened on the
  Paxeer chain (the test models this as `independently_finalized`). In the
  daemon this means a loopback JSON-RPC query (eth_chainId,
  eth_getTransactionReceipt(transaction_id): status 1, `to` == settlement
  contract, blockNumber == observed_block_number, a log from the contract
  carrying the checkpoint id; eth_blockNumber >= observed block). The C core
  has NO HTTP client for Paxeer (`src/paxeer/*.c` is ABI/verification only);
  the daemon has a loopback HTTP client for publishing to the replica
  (`lxp_daemon_authority_replica_publish`, `cmd/layerxd/lxp_daemon_authority_replica.c:762`)
  whose conventions can be reused. New env: `LAYERX_NODE_PAXEER_CHAIN_ID`,
  `LAYERX_NODE_SETTLEMENT_CONTRACT`, `LAYERX_NODE_PAXEER_RPC_ADDRESS`
  (127.0.0.1 only) / `_PORT`. In the pod, a loopback→TLS relay to the
  `paxeer-boundary` Service must exist (planned: a small relay mode/binary;
  the core boundary or paxeer crate is the natural home — see 6.7).
- Also verify the second claim in observation 6.3.1: `path_empty_or_absent`
  (`lxp_daemon_process.c:2763-2772`) + `lxp_log_open`
  (`src/storage/lxp_log.c:225-295`): a newly created log gets segment
  capacity; an existing zero-length file gets `capacity = st_size = 0` and
  the first `lxp_log_append` fails with `LXP_ERR_LENGTH_LIMIT`. Fresh
  bootstrap must work with absent files (and zero-length ones if the
  harnesses create them); the `--authority-replica` must grow its log too.
- Add `tests/daemon/lxp_test_finality_authority.c` (real anvil from
  `/root/.foundry/bin`, settlement contracts deployed, genuine registration
  verifies; mismatched chain id / contract / checkpoint id / block / reverted
  tx refused; unreachable chain → unavailability, never success) and a shell
  test that boots replica + sequencer from a fresh genesis and submits one
  SEND over the LNI. Wire both into the Makefile (`LAYERXD_SOURCES` at
  Makefile:1129; C test pattern at Makefile:1610-1620).

Note for 6.3's `[observation.6.3.2]`: the replica matches
`Authorization: Bearer ` case-sensitively with `strstr`; ureq 3.4 lowercases
header names → 401. Fix the replica to parse the header case-insensitively
(the registry's relay `platform/hosted/registry/src/node_state.rs:293` uses
ureq too).
